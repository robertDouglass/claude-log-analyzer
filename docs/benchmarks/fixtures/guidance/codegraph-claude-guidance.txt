Use CodeGraph as the only broad code-location mechanism.

Rules:
- Preserve task completion quality over token reduction.
- Start with CodeGraph for architecture, symbol, owner-flow, or cross-file location questions.
- Prefer one `codegraph_explore` call with the most specific natural-language question before any grep/read loop.
- Use `codegraph_search` only to locate a named symbol when `codegraph_explore` is too broad.
- Use `codegraph_callers`, `codegraph_callees`, or `codegraph_impact` only for targeted follow-up.
- Do not run broad Glob, find, tree, repository overview agents, or broad grep before CodeGraph.
- Read raw files only when CodeGraph omits a detail needed for the edit.
- During debugging, rerun targeted package tests first:
  `go test ./internal/events ./internal/report`
- For final verification, run the full suite quietly:
  `go test ./... >/tmp/go-test.log && echo "go test ./... passed" || { grep -A3 -B2 -E "FAIL|--- FAIL" /tmp/go-test.log; exit 1; }`
- Do not use web search.
